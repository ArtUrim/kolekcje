Raspberry Pi Installation Guide

This comprehensive guide describes how to configure your Raspberry Pi running moode.audio to also serve the kolekcje web application.

This setup integrates the kolekcje frontend directly into moode.audio's built-in Nginx server, runs the backend services containerized, and configures a smart-shutdown daemon.

Note: This guide is specifically designed for Raspberry Pi users running moode.audio with an existing nginx server. For standard Docker deployment, see the main documentation.

Architecture Overview

  • Frontend: Served as pre-rendered static files by moode.audio's host Nginx from /kolekcje/front
  • Backend & Database: The database and connector run inside containerized environments (Docker/Podman)
  • System Controls: A smart-shutdown system daemon is enabled on the host to manage clean power-offs

Prerequisites

  • Raspberry Pi with moode.audio installed and configured
  • Existing nginx server running on moode.audio
  • Docker and Docker Compose installed on the Raspberry Pi
  • Local DNS server (router or pi.hole) configured for moode.lan and kolekcje.lan domains
  • SSH access to your Raspberry Pi

Step 1: Prepare the Frontend (Nuxt Prerender)

Before moving files to the Raspberry Pi, you need to generate the static files of the kolekcje frontend.

  1. Navigate to your frontend source directory on your local machine:

    cd /path/to/kolekcje/front

  2. Build and pre-render the static files:

    npx nuxt build --prerender

    Note: This command generates static assets inside the local .output/public (or dist) directory.

  3. Inside running *front* container:

    npxdocker exec -w /front front npx nuxt build --prerender

  4. Transfer these files to your Raspberry Pi:

    # Create the target directory on your Raspberry Pi
ssh ${USER}@moode.lan "sudo mkdir -p /kolekcje/front && sudo chown -R ${USER}:${USER} /kolekcje"

# Sync the prerendered files to the target folder
rsync -avz .output/public/ ${USER}@moode.lan:/kolekcje/front/

Step 2: Configure Built-in Nginx

Rather than deploying a containerized reverse-proxy, we configure moode.audio's native Nginx instance to serve kolekcje alongside its own web UI.

  1. SSH into your Raspberry Pi:

    ssh ${USER}@moode.lan

  2. Modify file /etc/nginx/nginx.conf:

    --- Old/etc/nginx/nginx.conf
+++ New/etc/nginx/nginx.conf
@@ -33,34 +33,34 @@
+ 	# access_log off;
+ 	access_log /var/log/nginx/access.log;
- 	access_log off;
- 	#access_log /var/log/nginx/access.log;
    Important: This change is required for the smart-shutdown service. The activity on the webpages is monitored by watching for new entries in the nginx logs.

  3. Modify configuration of the moode service in nginx to grab only traffic for a specific host (moode.lan or moode.local):

    --- Old/etc/nginx/sites-available/moode-http.conf
+++ New/etc/nginx/sites-available/moode-http.conf
@@ -7 +7 @@
+ 	server_name moode.lan moode.local;
- 	server_name _; # Matches any hostname
    Note: This change requires your local DNS server (on router or pi.hole) to have specific rules for the FQDNs: moode.lan and kolekcje.lan (or the .local variants).

  4. Create a configuration for the new kolekcje subservice. Copy these two files:

    • nginx/etc/nginx/kolekcje-locations.conf → /etc/nginx/
    • nginx/etc/nginx/sites-available/kolekcje-http.conf → /etc/nginx/sites-available/

  5. Enable the configuration and test Nginx:

    # Enable site
sudo ln -sf /etc/nginx/sites-available/kolekcje-http.conf /etc/nginx/sites-enabled/

# Verify syntax
sudo nginx -t

# Reload Nginx to apply changes
sudo systemctl reload nginx

Step 3: Run Connector & DB from Containerized Environment

Prepare the containerized backend services using Docker/Podman on the Raspberry Pi.

  1. Ensure Docker and Docker Compose are installed, following the official Docker installation guide.

  2. Create a deployment directory:

    mkdir -p ~/kolekcje
cd ~/kolekcje

  3. Copy the compose-moode.yml file to the newly created directory:

    cp /path/to/kolekcje/compose-moode.yml ~/kolekcje/

  4. Start the services:

    docker compose -f compose-moode.yml up -d

Database Backup

Good practices recommend making a database backup periodically. The command for this in our environment:

docker exec mariadb mariadb-dump -u example -p'example' katalog > dbKolekcjeBck_$(date +"%d%m%Y_%H:%M").sql
Tip: Consider adding this command to a cron job for automated daily backups.

Step 4: Enable Smart-Shutdown Service

To ensure safe system cut-offs, configure and enable the smart-shutdown daemon on the host.

  1. Copy the systemd service template systemctl/smart-shutdown.service to /etc/systemd/system/ directory:

    sudo cp systemctl/smart-shutdown.service /etc/systemd/system/

  2. Copy the Python script systemctl/smart_shutdown.py to /usr/local/bin/:

    sudo cp systemctl/smart_shutdown.py /usr/local/bin/

# Add executable permissions to the script
sudo chmod +x /usr/local/bin/smart_shutdown.py
    Configuration Required: Edit the script to configure the Tasmota smart socket IP address and other settings according to your hardware setup.

  3. Enable and start the systemd service:

    sudo systemctl enable smart-shutdown.service
sudo systemctl daemon-reload
sudo systemctl start smart-shutdown.service

How Smart Shutdown Works

The smart-shutdown daemon monitors two types of activity:

  • HTTP Traffic: Watches nginx access logs for web requests to kolekcje
  • Audio Playback: Monitors MPD status and HiFiBerry hardware for active audio playback

If both HTTP and audio activity remain idle for the configured threshold (default: 30 minutes), the system will:

  1. Send a command to a Tasmota smart plug to delay shutdown by 5 minutes
  2. Execute a clean system shutdown
Test Mode: Run the script with -t flag to test without actually shutting down: python3 /usr/local/bin/smart_shutdown.py -t

Verification

To verify that your deployment was successful:

  • Navigate to http://moode.lan (or your Raspberry Pi IP) to verify moode.audio is operating normally
  • Navigate to http://kolekcje.lan to verify that your static Nuxt frontend is rendering and communicating with the backend container correctly

Troubleshooting

Nginx Configuration Errors

If nginx fails to reload, check the configuration syntax:

sudo nginx -t
sudo journalctl -u nginx

Backend Not Responding

If the frontend loads but cannot connect to the API:

# Check if containers are running
docker ps

# Check container logs
docker logs connector
docker logs mariadb

Smart Shutdown Not Working

Check the service status and logs:

sudo systemctl status smart-shutdown.service
sudo journalctl -u smart-shutdown.service -f
